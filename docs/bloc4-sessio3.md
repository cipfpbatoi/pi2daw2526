# Sessió 3. Organitzar l'execució

## Propòsit

Preparar un sistema de treball que permeta a una altra parella executar el pla i mostrar el progrés real.

## 1. Cronograma, fites i iteracions

Ordeneu les tasques segons dependències i capacitat. Definiu fites com a resultats verificables, no com a dates sense producte. Cada iteració ha d'acabar amb un increment o una prova observable i reservar temps per integrar, documentar i corregir.

## 2. Responsabilitats

Assigneu una persona responsable de coordinar cada tasca sense convertir-la en propietària exclusiva del coneixement. Indiqueu revisió, dependències i participació esperada. La parella executora podrà redistribuir el treball si registra el canvi.

## 3. Issues i tauler de GitHub

Creeu les issues concretes a partir dels formularis de la plantilla. Cada issue ha de contindre resultat, dependències, criteris d'acceptació, evidència esperada i estimació. Useu etiquetes i una fita per agrupar-les; el tauler mostra l'estat, però el pla explica el criteri.

No creeu una issue per cada línia de codi ni una única issue per tot un component. La unitat adequada permet revisar un resultat i atribuir responsabilitat.

## 4. Definició de fet i versions

Acordeu una definició comuna de tasca finalitzada: implementació o documentació revisada, proves superades, criteris d'accessibilitat aplicables, evidència enllaçada i issue actualitzada. Definiu branques, pull requests, revisió, etiquetes i versions del prototip.

## Evidència de sessió

Completeu les seccions 10–11 del pla i deixeu el conjunt inicial d'issues, fites i tauler preparat. Cada membre revisarà almenys una issue creada per l'altra persona.

## Comprovació

La parella executora pot seleccionar la primera tasca sense preguntar què significa ni com demostrar que està acabada?
