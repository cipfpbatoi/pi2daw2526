# Material d'ús docent: cas Som Barri

!!! danger "Material docent"

    Esta pàgina conté dades que l'alumnat haurà de descobrir mitjançant preguntes i les incidències que s'introduiran durant les activitats. No s'ha d'incloure en la navegació pública destinada a l'alumnat ni facilitar-se completa a l'inici.

## 2. Protocol per respondre preguntes

L'objectiu no és premiar qui endevine les preguntes exactes, sinó observar si l'equip identifica informació que afecta decisions importants.

Es recomana:

- respondre només allò que s'haja preguntat amb prou claredat;
- demanar a l'equip que explique quina decisió depén de la resposta;
- diferenciar les dades confirmades de les estimacions del client;
- permetre reformular preguntes massa generals;
- registrar «el client encara no ho sap» quan siga una resposta realista;
- donar la mateixa informació a tots els equips que formulen preguntes equivalents.

### Preguntes especialment significatives

| Àmbit | Pregunta esperable | Informació que es pot revelar |
| --- | --- | --- |
| Volum | Quantes activitats i participants gestioneu? | Volums de la fitxa completa |
| Procés | Com es fa ara una inscripció? | Canals actuals i còpia manual de dades |
| Usuaris | Qui gestionarà i qui utilitzarà la solució? | Perfils i competència digital |
| Dades | Es tracten dades de menors? | Sí, en algunes activitats |
| Cost | Quin pressupost hi ha? | 2.500 € inicials |
| Termini | Què significa «abans de quatre mesos»? | Prototip validable, no necessàriament producció completa |
| Pagaments | Cal cobrar des de la plataforma? | És una petició, però no s'ha decidit si entra en la primera versió |
| Accessibilitat | Hi ha necessitats específiques? | Persones majors i dificultats visuals |
| Manteniment | Qui mantindrà el sistema? | No hi ha personal informàtic propi |
| Èxit | Què voldria millorar l'associació? | Errors, visió de places, càrrega administrativa i avisos |

## 3. Orientació de resposta

No hi ha una única solució correcta. La documentació de cada equip hauria de mostrar una cadena coherent:

```text
necessitat → objectiu → criteri d'èxit → requisit → lliurable → tasca → prova
```

### Formulació acceptable del problema

La informació de les activitats i inscripcions està fragmentada entre diversos canals i es transcriu manualment. Això genera errors, duplicitats, falta d'informació actualitzada i dificultats de comunicació.

### Formulacions que requerixen revisió

- «El problema és que no tenen una aplicació web.»
- «Necessiten Laravel i una base de dades MySQL.»
- «El problema és que el seu sistema és antic.»

Estes frases confonen el problema amb una possible solució o no aporten evidències suficients.

### Possible objectiu general

Millorar la gestió de les activitats i inscripcions mitjançant un procés centralitzat que reduïsca els errors i facilite informació actualitzada a l'associació i a les persones participants.

No cal exigir esta redacció. S'ha de comprovar que l'objectiu responga al problema i tinga criteris d'èxit observables.

### Possible abast del prototip

- consulta d'activitats i places;
- inscripció a una activitat;
- confirmació de la sol·licitud;
- gestió bàsica d'activitats i inscripcions;
- recorregut accessible i adaptable a mòbil;
- prova amb dades fictícies representatives.

Podrien quedar fora:

- pagament en línia;
- aplicació mòbil nativa;
- integració amb totes les xarxes socials;
- migració completa de dades històriques;
- automatitzacions avançades;
- versió definitiva preparada per a producció.

Altres delimitacions també són vàlides si estan justificades.

## 4. Incidències

### Incidència comuna recomanada

> Una subvenció esperada no ha sigut concedida. El pressupost disponible es reduïx de 2.500 € a 1.500 € i la primera versió ha d'estar preparada tres setmanes abans.

S'ha d'observar si l'equip:

- identifica els lliurables i tasques afectats;
- revisa l'abast o les prioritats;
- actualitza costos, cronograma i riscos;
- conserva el recorregut de major valor;
- registra la decisió i qui l'hauria d'aprovar;
- evita limitar-se a reduir totes les estimacions sense justificació.

### Incidències alternatives

Es pot assignar una incidència diferent a cada equip:

1. **Accés mòbil:** la major part de participants només accedix des del telèfon.
2. **Menors:** la junta confirma que es gestionaran inscripcions de menors.
3. **Cost extern:** el servei d'avisos previst deixa de ser gratuït.
4. **Disponibilitat:** l'administrativa no podrà participar durant dues setmanes.
5. **Nova petició:** la junta demana incorporar pagaments en línia.
6. **Alternativa existent:** una persona voluntària troba una ferramenta gratuïta que cobrix part del procés.
7. **Llista d'espera:** algunes activitats superen habitualment el nombre de places.
8. **Conservació de dades:** la junta vol conservar totes les dades indefinidament.

La resposta correcta no és acceptar totes les peticions. Es valorarà la decisió argumentada d'incorporar, ajornar, substituir o rebutjar el canvi.

## 5. Correcció del diagnòstic

El diagnòstic és qualitatiu. Per cada resposta es pot registrar:

- `A`: aplica el concepte amb autonomia;
- `R`: l'aplica parcialment o necessita reforç;
- `N`: no aporta una resposta útil encara.

| Pregunta | Evidència buscada |
| --- | --- |
| Problema | Descriu la fragmentació o ineficiència del procés, no l'absència d'una app |
| Causa i conseqüència | Establix una relació causal plausible |
| Parts interessades | Inclou perfils directes i indirectes |
| Pregunta al client | Demana informació que afectaria una decisió |
| Objectiu | Expressa un canvi o resultat |
| Criteri d'èxit | Proposa una evidència observable |
| Lliurable i tasca | Diferencia resultat i activitat |
| Risc | Formula un esdeveniment incert i el seu efecte |
| Estimació | Identifica abast, recursos, dependències o incertesa |
| IA | Inclou finalitat, ajuda i verificació humana |

Els resultats permeten decidir quins conceptes necessiten una explicació breu abans de cada activitat.

## 6. Graella d'observació

| Alumne/a | Formula preguntes | Justifica decisions | Escolta i integra aportacions | Concreta tasques | Revisa el pla | Registra evidències | Observacions |
| --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |  |

Es pot utilitzar una escala breu:

- `2`: ho fa de manera autònoma i aporta evidències;
- `1`: ho fa amb ajuda o de manera irregular;
- `0`: encara no s'ha observat.

La graella no ha de convertir-se automàticament en una qualificació. La seua funció principal és orientar la retroacció i la formació posterior dels equips.

## 7. Retroacció del Dossier 0

Per evitar una correcció excessivament extensa, es recomana retornar:

1. una fortalesa concreta;
2. una decisió que necessita més justificació;
3. una incoherència entre apartats;
4. una millora prioritària abans del projecte real.

### Categories de revisió

| Categoria | Pregunta de revisió |
| --- | --- |
| Comprensió | El problema i les necessitats estan diferenciats de la solució? |
| Coherència | Objectius, abast, tasques, recursos i riscos estan connectats? |
| Justificació | Les decisions es basen en criteris, preguntes o evidències? |
| Adaptació | L'equip actualitza el pla quan canvien les condicions? |
| Traçabilitat | Es pot seguir la relació entre necessitat, requisit, tasca i prova? |
| Autoria | Es pot identificar la contribució de cada membre? |

## 8. Tancament del bloc

El bloc haurà complit la seua funció si permet:

- decidir quins continguts de primer necessiten reforç;
- detectar alumnat que planifica amb autonomia;
- observar dinàmiques de cooperació;
- disposar d'informació per proposar equips complementaris;
- establir un model reduït del procés que s'aplicarà al projecte real.

No es recomana reutilitzar els equips provisionals com a equips definitius de manera automàtica. La proposta final correspon a l'equip educatiu i ha de considerar el conjunt d'evidències i condicionants.
